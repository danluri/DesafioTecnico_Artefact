## Intent

**Problem:** The application has the real conversation pipeline and WhatsApp simulator, but no manual way to type a message and observe the response, session, LLM provider, and duplicate handling end to end.

**Approach:** Add a development-only HTTP server and a small browser console. The server accepts a local WhatsApp-shaped message, routes it through the existing webhook adapter, `ConversationService`, configured LLM, tools, and SQLite session repository, then returns a safe JSON result. The browser sends messages, keeps the returned session identifier, shows the assistant response and processing metadata, and can replay a message id to demonstrate deduplication.

**Always:** Bind only to an explicitly configured local host/port, keep the endpoint disabled in the normal production runtime, mark it as development-only, reuse the existing signature and mock channel boundaries, preserve authorization and provider configuration, and keep FakeLLM as the default.

**Never:** Expose the dev endpoint publicly by default, bypass `ConversationService`, accept real WhatsApp credentials in the simulator, expose private database data, or create a separate response path that behaves differently from the application pipeline.

</frozen-after-approval>

- Given the same message id is submitted twice, then the second response reports duplicate handling without processing the conversation twice.
- Given a returned session id, when the user submits a follow-up, then the same conversation session is reused.
- Given malformed JSON, oversized text, invalid methods, or provider failure, then the endpoint returns bounded safe errors without a traceback.
- Given default Docker startup, then no development endpoint is exposed and readiness behavior remains unchanged.

## Implementation Notes

- Use Python standard-library HTTP primitives to avoid adding a web framework dependency for a test-only surface.
- Use a synthetic local WhatsApp signature generated by the existing simulator; the endpoint must never call Meta.
- Bind to `127.0.0.1` by default and require `EMPORIO_DEV_CONSOLE_ENABLED=true` plus an explicit `--dev-console` runtime flag.
