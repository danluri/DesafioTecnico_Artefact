- (constraint) The final PRD is the governing product contract: FR-1 through FR-14, UJ-1 through UJ-4, and the P0/P1 boundary are inherited without reinterpretation.
- (constraint) Existing ADR-001 through ADR-004 are adopted as source constraints: normalized LLMPort, hybrid SQL plus policy retrieval, optional integrations, and Ponytail outside runtime.
- (decision) AD-1 will use Hexagonal Architecture (Ports and Adapters) with Domain, Application, Ports, Adapters, and Delivery boundaries; this prevents provider, database, and channel choices from leaking into business rules.
- (decision) AD-2 will assign ownership of Product, Promotion, payment, shipping, availability, Policy provenance, and Order ownership rules to deterministic domain/application services; the LLM may propose tool calls but never owns these facts.
- (decision) AD-3 will enforce inward dependency direction: delivery and infrastructure may depend on application, domain, and ports; domain may depend only on standard-library abstractions and domain types.
- (decision) AD-4 will keep operational snapshot queries and policy retrieval as separate ports and data paths; exact values use structured repositories while policy answers use section-aware retrieval with provenance.
- (decision) AD-5 will normalize all LLM providers behind LLMPort and LLMFactory with explicit capabilities; FakeLLM is mandatory for offline tests and unsupported tool-calling capability fails before execution.
- (decision) AD-6 will expose only an allowlisted ToolRegistry with schema validation, server-side authorization, timeouts, and a hard tool-round budget; arbitrary SQL, shell, dynamic imports, and unknown tools are forbidden.
- (decision) AD-7 will make Authorized Principal server state the only authority for Order access; channel text, order IDs, names, phone numbers, and emails cannot authenticate a Customer.
- (decision) AD-8 will route CLI, HTTP, and future WhatsApp messages through one ConversationService using normalized inbound/outbound message contracts; channel adapters must not contain domain rules.
- (decision) AD-9 will use SQLite as the P0 local persistence boundary, separating operational snapshot tables, policy chunks/index, session data, and optional market observations; each aggregate has one write owner.
- (decision) AD-10 will keep WhatsApp, market comparison, and MCP behind feature flags and ports; their failure or absence must not prevent the offline P0 path.
- (decision) AD-11 will emit structured sanitized observability events with correlation IDs, session hash, provider/model, tool outcome, duration, and error class; raw prompts and customer PII are excluded by default.
- (decision) AD-12 will define local reproducibility as the primary deployment envelope: Python project managed by uv, SQLite, FakeLLM, deterministic fixtures, and no external credentials required for the core suite.

- (version) Official documentation checked during authoring confirms FastAPI remains actively documented, Pydantic v2 validation is available, and SQLite FTS5 provides full-text search; exact dependency pins remain a project bootstrap decision.
